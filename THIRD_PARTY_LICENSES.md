## Client-side Haxe compiler (web playground)

The web playground compiles `.hx` to `.lua` entirely in the browser using a
WebAssembly build of the Haxe compiler. These artifacts are generated by
`web/scripts/gen-haxe-assets.mjs` into `web/public/haxe-wasm/` (gitignored) from
the build recipe in `spike/`.

| Component | Path (generated) | License | Source |
|-----------|------------------|---------|--------|
| Haxe compiler (WebAssembly, **modified**) | web/public/haxe-wasm/code-*.wasm | **GPL-2.0-or-later** | https://github.com/HaxeFoundation/haxe @ 5.0.0-preview.1 + patch `spike/patches/haxe-5.0.0-preview.1-wasm.diff` (reproducible via `spike/Dockerfile`) |
| Haxe standard library | web/public/haxe-wasm/std-bundle.json, prelude | MIT | https://github.com/HaxeFoundation/haxe (`std/`) |
| OCaml runtime + stdlib (compiled into the wasm) | (in code-*.wasm) | LGPL-2.1-with-linking-exception | https://github.com/ocaml/ocaml |
| wasm_of_ocaml runtime (in the JS glue) | web/public/haxe-wasm/haxe.js | MIT (LGPL-2.1 parts w/ linking exception) | https://github.com/ocaml-wasm/wasm_of_ocaml |

GPL-2.0-or-later note: the bundled Haxe compiler `.wasm` is a **modified** Haxe
compiler, so distributing it (e.g. the deployed playground) carries GPL-2.0
obligations. The corresponding source is satisfied by this public repository:
upstream Haxe at tag `5.0.0-preview.1`, the patch under `spike/patches/`, and
the reproducible build in `spike/Dockerfile`. The Haxe compiler being bundled as
an invoked tool is mere aggregation; lub's own code (C runtime, web playground
TypeScript, samples) remains MIT and is not a derivative of the compiler.
