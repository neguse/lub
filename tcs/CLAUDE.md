# TinyC# (tcs) — C#サブセット → Lua 5.5 トランスパイラ

## プロジェクト概要

C#の小さなサブセットをフロントエンド言語とし、Lua 5.5ソースコードをバックエンドとするトランスパイラ。
フル C# / フル BCL ではなく、モダンな .NET / C# 開発体験を満たす最小ラインを選び、Go のようなコンパクトさを保つ。
Rider など標準的な C# ツールキット上で tcs 準拠コードかをリアルタイム確認できる Roslyn Analyzer も開発体験の中核に置く。
詳細は `objective.md` を参照。

## ビルド・テスト

### 前提

- .NET 10 SDK / C# 14 — SDK 版は `global.json` で固定し、Dependabot (`dotnet-sdk`) が
  bump PR を出す。マシンへの導入は `dotnet-install.sh --jsonfile global.json` の
  per-user install (distro package と混ぜると workload manifest が更新で消えて壊れる)
- CMake 3.12+ / C compiler (Lua 5.5 build)
- Lua 5.5 (`deps/lua/lua` or `deps/lua/lua.exe`)

### コマンド

```bash
# 初回セットアップ: pre-commit ゲート (.githooks/pre-commit = run-tests.sh) の配線
git config core.hooksPath .githooks

# テスト実行（基本操作）
dotnet test

# 準拠チェック（Lua 出力なし、警告/エラーで exit 1）
dotnet run --project Transpiler -- check input.cs --ref engine-stub.cs

# トランスパイラ実行
dotnet run --project Transpiler -- input.cs -o output.lua

# Lua 5.5 ビルド
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release

# Lua でトランスパイル結果を実行
deps/lua/lua output.lua

# 全テスト（シェルスクリプト）
bash run-tests.sh
```

`run-tests.sh` / `run-tests.ps1` は Lua binary が未生成・stale・Lua 5.5 でない場合に CMake で再ビルドし、`dotnet test`、代表 sample の `tcs check`、analyzer-demo build の expected diagnostics 検証、analyzer nupkg の PackageReference consumer / `.editorconfig` severity override 検証を実行する。Rider helper script (`verify-rider-scripts.sh`) の検証は `run-tests.sh` のみ。
analyzer / `tcs check` / transpiler warning の診断一致は run-tests のこの恒常ゲートで守る（個別タスクにはしない）。

## 開発ワークフロー

### 作業手順

1. `doc/tasks.md` から次のタスクを選択（残作業の正本。直近の文脈は `doc/done.md` 末尾と `git log`）
2. テストを先に書く（TDD）
3. 実装し、`dotnet test` で全テスト通過を確認
4. `doc/done.md` に完了ログを記録し、`doc/tasks.md` から削除
5. コミット（1タスク = 1コミット）

進捗スナップショット（旧 doc/current.md）は持たない。仕様の正本は
support-matrix / README / design doc、歴史は done.md と git log。

### 完了ログ形式（done.md）

- [実施内容]（変更ファイルの列挙は不要 — commit が正本）

## コード規約

### 命名

- 「spike」という名称は使わない（識別子・ファイル名・新規ドキュメントとも）。
  旧 spike 由来の実体はすべて `perf` 系の名前を使う
- tcs / tcs2c はプロジェクト全体のリブランディング（時期・名称未定）を控えた
  暫定名。新規の命名は tcs 系に揃える

### C# (.NET 10 / C# 14)

- `<TargetFramework>net10.0</TargetFramework>` / `<LangVersion>14</LangVersion>`
- nullable enable（全プロジェクト）
- テストは xUnit + FluentAssertions スタイル
- Roslyn の `Microsoft.CodeAnalysis.CSharp` パッケージを使用

### Lua 出力

- インデント: スペース2つ
- Lua 5.5 互換のみ（5.4以前の機能に依存しない）
- 生成コードにはヘッダコメントを付与: `-- Generated by TinyC# transpiler`

### テスト方針

- **セマンティックテスト**: C#入力 → トランスパイル → Lua VM実行 → 結果検証
- 出力文字列の完全一致テストは使わない（Lua出力形式の変更に弱い）
- `TranspileAndRun(csharpSource, luaExpr)` ヘルパーで統一
- Lua 5.5 バイナリ (`deps/lua/lua`) をプロセス起動して実行

## トランスパイル方針

### 基本マッピング

| C#                  | Lua 5.5                            |
|---------------------|------------------------------------|
| class               | table + metatable                  |
| struct / record struct | plain table + copy 地点で型別 `__copy`（member は静的自由関数、static と operator は class と同じ、readonly は copy 省略。override は ToString だけ） |
| enum                | integer 定数テーブル                |
| method              | function(self, ...)                |
| static method       | function(...)                      |
| property            | getter/setter メソッド              |
| field               | table フィールド                    |
| List\<T\>           | sequence table `{v1, v2, ...}` (null を入れると長さを `n` に持つ) |
| Dictionary\<K,V\>   | hash table `{[k]=v, ...}`         |
| lambda              | function(...) ... end              |
| interface           | 自身の出力なし。実装する class の table に `__interfaces` |
| namespace           | 型を namespace 修飾名の global にする (`A.B.C` → `A_B_C`) |
| string interpolation| string.format                      |

### compiler の実装と Roslyn

- compiler はセルフホストの実装 1 つ (`SelfHost/Compiler/`、TinyC# で書く)。字句、構文、宣言、束縛、準拠検査、IL、Lua の出力、C backend への IL の書き出し、generic の単相化を持つ。C backend (`SelfHost/CBackend/`) と tcs VM の backend (`SelfHost/VmBackend/`) も TinyC# で、`tcs c` と `tcs vm` で動く。.NET、Lua、C、wasm のどれでも同じ実装が動く (設計は `doc/self-hosting-design.md`)
- CLI (check、変換、`--watch` と reload chunk、`--snapshot` と増分 session、source map) も TinyC# (`SelfHost/Tool/`) で、OS に触る所は `TcsHost` の関数にして host が実装する。host は .NET (`Transpiler/DotnetHost.cs`)、C (`SelfHost/Native/host.c`、tcs2c で C にした tcs)、Lua (`SelfHost/Host/tcsc.lua`)。`SelfHost/build.sh` が 3 つの経路の出力の一致を確かめる
- Roslyn は compiler の外の道具としてだけ使う: IDE の Roslyn Analyzer (`TinyCs.Analyzers`)、playground の補完と hover (`SemanticQueries`)、検証の oracle (C# として正しいかの判定と .NET での実行の比較)
- Roslyn Analyzer は compiler (`SelfHost/Compiler`、netstandard2.0 で analyzer に入れる) を動かし、`tcs check` と同じ TCS1001〜1003 を報告する (準拠の規則は compiler の 1 か所)。`--ref` の stub は AdditionalFiles の `TinyCsRef="true"` で渡す。TCS1004 (System.Math の超越関数が .NET の実装で動く) だけは analyzer が Roslyn で見る
- `TCS1001`: 未対応構文 (`try`, `throw`, local function, list pattern, Equals の override など)
- `TCS1002`: 未対応 BCL API / core library allowlist 外 member (`Math.Cbrt`, `List.Reverse`, `Enumerable.Single` など)
- `TCS1003`: Lua table で表現できない配列と Dictionary の null 保存

## 外部エンジン連携メモ

tcs のコア目的は engine agnostic な C# サブセット → Lua 5.5 トランスパイラであり、lub3d への直接対応は現時点の前提ではない。
lub3d 側のプロジェクト方針が変わっているため、以下の TinyCSharpGen 案は過去の検討メモとして扱う。実装タスクに戻す場合は、その時点の lub3d 側設計を読み直してから判断する。

### 旧案: lub3d API interface 生成（TinyCSharpGen）

lub3d の Generator パイプラインに乗せて C# interface を自動生成する案。

### アーキテクチャ

```
Clang AST → TypeRegistry → ModuleSpec（既存IR）
                                ├→ CBindingGen.Generate()   → .c  (既存)
                                ├→ LuaCatsGen.Generate()    → .lua (既存)
                                └→ TinyCSharpGen.Generate() → .cs  (新規)
```

### BindingType → C# 型マッピング

| BindingType       | C# 型           |
|-------------------|-----------------|
| Int               | int             |
| Int64             | long            |
| UInt32            | uint            |
| Float             | float           |
| Double            | double          |
| Bool              | bool            |
| Str               | string          |
| Void              | void            |
| Struct(_, _, lua) | class名         |
| Enum(_, lua)      | enum名          |
| Callback(p, r)    | Action/Func     |
| Vec2              | Vector2         |
| Vec4              | Vector4         |
| Ptr(inner)        | inner（透過）    |
| VoidPtr           | nint            |

### 生成物の配置

- lub3d の `Generator/TinyCSharp/TinyCSharpGen.cs` に実装
- 出力先: tcs の `TinySystem/` または `gen/` ディレクトリ
- lub3d の `Program.cs` に `TinyCSharpGen.Generate(spec)` 呼び出しを追加

## 既知の制約・注意事項

- dotnet と Lua の数値精度差異（double vs Lua number）
- 文字列: UTF-8 と定める。.NET の string だけが UTF-16 なので、位置を扱う API (`Length`、`Substring`、`IndexOf`、添字、`foreach (char c in s)`) は TCS1002 で止め、`TinySystem.Text` を使う
- struct / record struct: 値セマンティクス対応済み (T219b)。override は ToString だけ
- null vs nil: C# の null は Lua の nil にマップ
- 型消去: ジェネリクスはコンパイル時のみ、Lua出力には型情報なし
