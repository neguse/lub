# ドキュメント方針

lub のドキュメントは全て「live doc」つまり履歴を含まずlubがどうあるべきかを示している状態を保つ。
一時的にdocとcodeのずれ(設計~実装のタイムラグ等)があることは許容するが、極力整合している状態を保つ。
ドキュメントは平易な語で書く。開発 jargon(spike 等)・圧縮英語(版=revision等)・強調記法(bold)は使わない。
複数個所に同じ内容の記述が出現しないようにする。ただし粒度が違う場合(概要〜詳細等)は許容する。
ドキュメントファイルには実装に直接紐づかない内容(哲学、手順、ベンチマーク結果等)を記述し、実装に紐づく内容はコードコメントとして記述する。

## 検査

`scripts/docs-lint.sh` によりコミット前フックやCIで検査を行う。
