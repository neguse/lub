# XR (OpenXR / WebXR)

`Xr` は VR ヘッドセットの視点とコントローラー入力を、他の API と同じ immediate な形で返す。
ネイティブ (OpenXR) と Web (WebXR) でゲームの書き方は共通。

## API の概要

| API | 内容 |
| --- | --- |
| `Xr.Active()` | XR セッションが動いているか |
| `Xr.Focused()` | 入力フォーカスを持つか (システムメニュー表示中は `false`) |
| `Xr.View(eye, near, far)` | 片眼の `XrView` (左 `0`、右 `1`)。そのフレームに描けないときは `null` |
| `Xr.Input(hand)` | 片手の `XrInput` (左 `0`、右 `1`)。セッション外では `null` |

- `XrView`: 描画先 `Target`、解像度 `Width` / `Height`、LOCAL 空間での眼の位置 `Position` (メートル) と向き `Orientation` (`xyzw`)、行優先の `ViewProjection` 行列 (`float[16]`、`projection * view`) を持つ。OpenXR / WebXR の規約に従い右手系・前方 -Z・深度 `[0, 1]` で、通常の 3D (`Camera3d` / `Mat4` の左手系・前方 +Z) とは手系が逆になる。
- `XrInput`: `Active`、スティック `StickX` / `StickY`、トリガー・グリップ `Trigger` / `Grip` (`0`〜`1`)、ボタン `Primary` / `Secondary` / `Menu` / `StickClick` を持つ。

## 片眼へ描く

眼の描画先は `XrView.Target` で、`PassOpts.Target` に渡す (`Gfx.MainTex` と同じ扱いで、深度は既定のものを使い、他のターゲットとは組み合わせない)。`Xr.Active()` が `true` の間に `Gfx.MainTex` へ描くとエラーになる:

```csharp
public static void OnFrame(float dt)
{
    if (!Xr.Active())
    {
        Gfx.BeginPass(new PassOpts { Target = Gfx.MainTex });
        bindings.Set("mvp", Camera3d.Vp(camera)); // Mat4 (左手系・前方 +Z)
        DrawScene(bindings);
        Gfx.EndPass();
        return;
    }
    for (var eye = 0; eye < 2; eye++)
    {
        var view = Xr.View(eye, 0.05f, 500);
        if (view == null) return;
        Gfx.BeginPass(new PassOpts { Target = view.Target });
        anchor.ViewProjection(view, viewProjection); // float[16] (右手系・前方 -Z)
        bindings.Set("mvp", viewProjection);
        DrawScene(bindings);
        Gfx.EndPass();
    }
}
```

- 両眼とも描いたフレームだけがヘッドセットへ送られる (片眼のみ、または `View` が `null` のフレームは送られない)。
- MRT や後処理が必要な場合は自前のオフスクリーンターゲットへ描き、最後のパスで `Target = view.Target` へ合成する。

## 基準姿勢 (`Lubx.XrAnchor`)

LOCAL 空間は起動時の頭の位置が原点になる。ゲーム開始時やユーザー操作で基準を取り直すには `Lubx.XrAnchor` を使う:

```csharp
static readonly XrAnchor anchor = new XrAnchor();
static readonly float[] viewProjection = new float[16];

var left = Xr.View(0, 0.05f, 500);
var right = Xr.View(1, 0.05f, 500);
if (left != null && right != null) anchor.Recenter(left, right);
```

`Recenter` は両眼の中点と水平方向の向きを基準に取り、`ViewProjection(view, result)` がその基準を原点・前方 -Z とする行列 (行優先 `float[16]`) を書き出す。傾き (pitch / roll) は含めないため床は水平に保たれる。

## コントローラー入力

- スティックとトリガーは毎フレームの生の値のため、しきい値やヒステリシスはゲーム側で判定する。
- `Active` が `false` の手は未接続またはスリープ中。フォーカスを失うと両手の `Active` が `false` になる。

## キャプチャ (`--capture`)

XR 中の `--capture` は左右の眼を横に並べた 1 枚の PNG (幅は片眼の 2 倍) を保存する。
保存対象はヘッドセットへ送られる両眼描画済みのフレームのみで、それ以外のフレームは最大 120 フレーム飛ばして待つ (超えると失敗して終了)。
`--capture-frame` は起動からのフレーム数のため、装着や VR 入室までの時間を見込んで大きめに指定する。WebXR でセッション開始前に発火すると通常の平面画面を撮る。

## ネイティブ (OpenXR) と Web (WebXR)

### ネイティブ (OpenXR)

Linux と Android の Vulkan グラフィックスバックエンドに対応する:

- Linux 等では `LUB_BACKEND=openxr` で起動する。OpenXR ランタイム (SteamVR 等) と `XR_KHR_vulkan_enable2` が必要。SDL ウィンドウは非表示で作られ、`OnFrame` の `dt` には OpenXR の予測表示時刻の間隔が渡される。
- Android (Meta Quest) のプレイヤーは既定で OpenXR を使う。

### Web (WebXR)

同梱の `bin/wasm/xr.mjs` の `createXR` を使うと、ページ上のボタンで `immersive-vr` セッションの開始と終了を扱える:

```js
import { createXR } from "./xr.mjs";

const xr = await createXR({
  canvas, // プレイヤーが描く canvas
  button, // セッションを開始・終了するボタン
  getModule: () => window.Module, // プレイヤーの Emscripten Module
  report: (error) => console.error(error), // セッション中のエラー
});
// プレイヤーの初期化が終わったら呼ぶ
xr.ready();
```

- `createXR` は WASM を読み込む前に呼ぶ。
- `maxDimension` で片眼描画先の長辺上限を指定でき、`unlockAudio` にユーザー操作時の音声再開処理を渡せる。
- セッション中は両眼の sRGB 出力を canvas に左右に並べ、WebGL の XR レイヤーへ転送する。
