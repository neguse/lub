# Lider の窓の仕組み: 作る物

> 記録: 2026-11-15 に始めた、Lider の窓の仕組みの設計。作ると決めた物を書き、話し合いで決まるたびに足す。ここに無い物は、まだ話していないだけで、作らないと決めた物ではない。

## 考え方

- 枠組みに要るのは、どういう要件でも満たせて、そのうえで自然で快適なこと。1 つの体験から決め打ちしない。
- 表示ごとに専用の UI を作らない。どの表示も、ウィンドウ、スクリーン、ワールドの 3 つの層に載せる。
- 最初に作るのは、特定の配置でなく、どの中身のウィンドウも、どのスクリーンにも置けて、描けて、入力が届くこと。

## ワールド

- 基底はワールド (コードでは `Space`)。デスクトップの画面は、ワールドをカメラで 2D に投影したもの。XR では、同じワールドを頭の位置から見る。
- XR のための決まりは作らない。配置のデータは、デスクトップと XR で同じ物を使う。

## スクリーン (`Screen`)

- ウィンドウを並べる面。ワールドの中に置く。
- 持つ物: 形 (`Plane` / `Cylinder`)、固定先、位置 (`Position`)、大きさ (`Size`)、透過度、規則 (`ILayout`)、ウィンドウの順番。
- 固定先は、視点 (`ScreenAnchor.View`) と世界 (`ScreenAnchor.World`) の 2 つだけ。スクリーンがウィンドウに付いていく固定先は作らない。
- `ScreenAnchor.View` は見る人に固定する意味で、デスクトップではカメラ、XR では頭に固定される。XR で頭に付くのが合わないスクリーンは、利用者が `ScreenAnchor.World` に変える。
- 平面のスクリーンは、固定先によらず、同じに描けて、押せる。
- 初めから入っている左右に並ぶ形のスクリーン (`backdrop`) は、`ScreenAnchor.World` にする。デスクトップでは見え方は変わらず、XR では頭に付いてこない面になる。
- 奥行きを別に持たず、位置で表す。
- 持って動かせる。動かすとワールドの中の位置が変わり、上のウィンドウは並びを保ったまま付いてくる。
- どこにあるかが目に見えるようにする。Alt を押している間だけ、スクリーンの輪郭と名前の札を出す。
- 名前は、スクリーンを見分ける短い名前で、札にそのまま出し、控えた配置もこの名前でスクリーンを指す。今あるのは `backdrop` (ゲームの絵)、`code` (`Code` と `Inspector`)、`palette` (検索とアセット)、`hud` (操作の案内)。
- 動かすのは、名前の札を右ボタンでつかんで行う。面に沿って動き、つかんだままホイールで手前と奥へ動く。
- 円筒のスクリーンは、動かしても曲がりを変えない (曲がりの半径は決まった値で、奥へ動かすと、曲がったまま遠ざかる)。
- 固定先は、命令 (`screen:anchor`) で替える。
- 動かせるのは、動かす意味のあるスクリーンだけにする。`code` は動かせる (見やすい位置と距離にする)。`palette` (呼んだときだけ真ん中の上に出る) と `hud` (どの隅に出すかは規則の設定で替える) は動かさない。`backdrop` は、デスクトップでは画面いっぱいなので動かさず、XR でどうするかは XR を触るときに決める。
- できる操作: 作る、消す、動かす、大きさを変える、固定先を変える、規則を替える、出す / 隠す、透過度を変える。
- ゲームの絵を出す奥のスクリーンの名前は `backdrop`。

## ウィンドウ (`Window`)

- 画面に出す物は全部ウィンドウにし、中身を `IContent` で持つ。
- スクリーンの面の上の矩形を足場にする。並べる単位は平面。中身は、その前後に厚みを持って描ける。
- `Position` (`Vec3`) は、スクリーンの座標での真ん中の位置。X が右、Y が上、Z が奥 (0 が面の上、負が手前)。`Size` (`Vec2`) は幅と高さ。`UnscaledSize` は倍率 1 のときの幅と高さ。
- 手前か奥かは、位置 (`Position` の Z) で表す。浮かせた窓のような別の種類は作らない。手前に出ていることは、位置と透過度で見せる。
- 親を持てる。子の位置は、親の中身が親の座標で決め、子は親より手前に置く。
- 持って動かせる。動かすと、スクリーンの中の順番が変わる。
- できる操作: 開く、閉じる、順番を変える、別のスクリーンへ移す、focus を移す。
- 閉じるのは、どのウィンドウにも同じに効く操作にする。どのウィンドウにも見出しの帯と閉じる印を出し、Ctrl+W は focus のあるウィンドウに効く (`Code` では今のタブを閉じ、最後のタブなら窓ごと閉じる)。
- 見出しの帯は、どのウィンドウにも、focus や枚数によらず、いつも出す。帯なしでゲームの絵だけを見るのは、lider の物を隠す操作 (ゲームだけにする) で行う。帯の置き場所、当たり、描くのは、中身によらず 1 つの経路にし、XR でも同じに出して、印を押せるようにする。閉じられないウィンドウ (保存済みの版のゲームの絵) には、閉じる印を出さない。編集中の版のゲームの絵の閉じる印は、並べるのをやめる。

誰の物かで、扱いを分ける。

| 誰の物か | 扱い | 例 |
|---|---|---|
| あるウィンドウ | そのウィンドウの子にする | 補完の候補、かなの変換の候補、そのウィンドウのメニュー |
| 誰の物でもない | 親を持たないウィンドウにする | 検索 (`SearchView`)、操作の案内 (`HintCard`) |

カーソルは構造の外に置く。指す ray が当たった点の印で、入力の当たりの相手にはならない。

## 並べ方 (`ILayout`)

- タイル型のウィンドウマネージャのやり方にする。スクリーンが持つのはウィンドウの順番だけで、規則が位置を決める。
- 規則は `ILayout` を実装すれば足せ、切り替えられる。枠組みは個々の規則を知らない。
- 規則が並べるのは、親を持たないウィンドウだけ。子が出ても消えても、並びは変わらない。
- 規則ごとの設定 (先頭に 1 枚ずつ並べるウィンドウの数、列の幅の割合、積んだウィンドウの高さの割合) は、利用者が操作で変える。中身を見て形を変える特別扱い (編集中の版を出したら列を増やす、など) は入れない。
- ウィンドウの端を引いて大きさを変える操作は、どの規則でも同じにする。枠組みは、引ける端と、大きさを変えることを規則に聞くだけで、どの境目がどう動くかは規則が決める。変えた設定は、規則の設定として配置に控える。
- `保存済み | 編集中 | Code / Inspector` のような形は、名前の付いた形として持たず、区画に割る規則 (`MainStack`) の設定 (先頭に並べる数を 2 にする) とウィンドウの順番で作る。
- 保存済みの版と編集中の版を、左右にも上下にも並べられる。エディタは、ゲームと並べることも、透過で重ねることもできる。
- 配置全体を、名前を付けて控え、戻せる。重ねる形も左右に並ぶ形も、控えた配置の 1 つ。
- 配置 (`Arrangement`) が持つ物は、スクリーンごとの名前、形、固定先、位置、大きさ、透過度、規則と、どのウィンドウがどのスクリーンに、どの順で居るか。
- ウィンドウは、`Code` は開いている file の並び、ゲームの絵は版、`Inspector` は 1 つだけ、で見分ける。控えた時に無かった `Code` のウィンドウは、戻すときに、コードを置くスクリーンの最後に足す。
- 初めから入っている配置は、左右に並ぶ形 (左にゲームの絵、右の上に `Code`、右の下に `Inspector`) と、重ねる形 (ゲームの絵が画面いっぱいで、手前に `Code` が透けて重なる) の 2 つ。起動したときは、左右に並ぶ形にする。
- 命令は、今の配置を控える (`arrange:save`)、名前の配置に戻す (`arrange:<名前>`)、次の配置へ (`arrange:next`)。
- 控えるときの名前は、検索の欄に打って決める。同じ名前なら上書きする。
- 控えた配置は、プロジェクトの下の `.lider/` に書く (プロジェクトごとに別)。file は、1 行に 1 つの項目を書いたテキスト。

## 中身 (`IContent`)

| 中身 | 何か |
|---|---|
| `Code` | file を開いた窓。タブ付き |
| `GameView` | ゲームの絵。保存済みの版か、編集中の版 |
| `Inspector` | ゲームの値の木 (`InspectView`)。負荷の一覧も出す |
| `Search` | 検索 (`SearchView`) |
| `Asset` | 画像と音 (`AssetView`) |
| `Hints` | 操作の案内 (`HintCard`) |
| `Osk` | 画面のキーボード (`OskView`) |

- ゲームの動いている版との差分は、`Code` の見せ方の 1 つ。本文の中に出す形は、`Code` の矩形の中に描く。左右に並べる形の板は、`Code` のウィンドウの子にして、親の左の手前に出す (並びは変えない)。
- 控えた frame の帯は、独立した物にせず、`GameView` のウィンドウの一部として、ゲームを止めている間だけ出す。ゲームの絵を縮めずに、絵の下の端に重ねて描く。
- `GameView` のウィンドウは、ゲームの絵のほかに、Lider が足す要素 (控えた frame の帯、版の名前の札) を持つ。
- `Inspector` と、コードの横の値、負荷の一覧、絵を指してコードを探す操作は、同じ 1 つの版のゲームを見る。見る版は、最後に focus を置いたゲームの絵のウィンドウの版で、編集中の版を閉じたら保存済みの版に戻る。版を並べている間は、見ている版の名前を `Inspector` の見出しの帯に出す。
- `Inspector` のウィンドウは、`Code` と同じスクリーンに置く。重ねる形ではコードのスクリーンの一番左、左右に並ぶ形では `backdrop` の右半分に積まれる 1 枚になる。命令で開き、開いていればそこへ focus を移し、focus があるときにもう一度呼ぶと閉じる (閉じるのは汎用の操作を呼ぶ)。
- 操作の案内は、マウスで指した所の横に出すのをやめ、右下の決まった場所に出す。ゲームのボタン表示と同じ置き方にする。
- 画面のキーボード (`Osk`) は、普通のウィンドウとして出す。どのスクリーンにも置けて、デスクトップでもマウスで押せる (XR 専用の物にしない)。key を押すと、つないだキーボードと同じ key の event を流す。Shift、Ctrl、Alt は、押すと次の 1 打に効く。並びは US 配列。出し入れは命令 (`keyboard:toggle`) と、左手の Y。最初に出す所は、正面の下の手前。Steam の画面のキーボードは使わない。

## ゲームの出し方

ゲームは 2 通りに出せる。

- ゲームの絵を、スクリーンの上のウィンドウとして出す。
- ゲームが 3D の場面を描く場合に、絵にしてウィンドウに貼るのでなく、見る人のカメラ (デスクトップではワールドを投影するカメラ、XR では左右の目) で、ゲームの場面そのものを描く。ゲームの中の物は、ウィンドウやスクリーンと同じワールドの座標に立体として在り、XR では中に入って見回せる。

どちらで出すかは、`GameView` のウィンドウの置き場所で決まる。

- `GameView` のウィンドウの置き場所に、スクリーンのほかに `Space` (ワールド) を足す。スクリーンに置けば絵のウィンドウ、`Space` に置けば場面として出る。
- `Space` に置ける `GameView` は 1 つ。別の `GameView` を置いたら、前の物は元のスクリーンのウィンドウに戻る。保存済みの版を `Space` に置き、編集中の版を絵のウィンドウで並べる、はできる。
- 出し入れは、ウィンドウそのものを動かして行う。命令や一覧で選ばせない (ゲームや版が増えても、命令が増えない)。見出しの帯の、閉じる印の隣の印で `Space` へ出し、Alt を押している間に出る `Space` の札の印で、元のスクリーンに戻す。
- 配置を控えると、`Space` に置いた物も一緒に控える。

ゲームが見る人を受け取る口は、lub に元からある物をつなぐ (lider のための口を lub に足さない)。

- ゲームが見る人を受け取る口は `Xr`。app を開いた側が、開いた app に外の世界をどう見せるかを決める口は `App.Step` の `StepInput`。
- 開いた app も普通の app なので、`Xr` をそのまま使える。
- `StepInput` に、開いた app に見せる `Xr` を足す。隠す、そのまま見せる、開いた側が用意した見る人 (カメラと描き先) に差し替える、ができる。
- ゲームの側に新しい API は足さず、宣言もさせない。`Xr` を使って描くゲームは、`Space` に置くと見る人のカメラで描かれ、使わないゲームは、自分のカメラの絵のままになる。
- lider は、スクリーンに置いたゲームには `Xr` を隠し、`Space` に置いたゲームには、XR なら眼をそのまま、デスクトップなら lider のカメラを見せる。

## ゲームの状態を控える

- 好きな時点のゲームの状態を、名前を付けて控え、後でそこへ戻れる。命令は、控える (`state:save`。名前は検索の欄に打ち、同じ名前なら上書きする) と、戻す (`state:load:<名前>`。控えるたびに増える)。
- 控えるのも戻すのも、lider が見ている版 (`Inspector` が見ている版) のゲームにする。
- 戻したら、その状態から動き続ける。止めている間に戻しても、続ける。
- 控えた後にコードを変えて型の形が変わっても、戻せる。状態の読み込みは、コードを保存したときの反映と同じ決まりで形の違いを移す (field は名前で対応させ、種類と型が同じなら控えの値、足した field と型を変えた field は初期化子の値、消した field は捨てる)。この決まりは lub (tcs の VM) の側に置き、時間を戻す控えも同じ読み込みを通る。
- 読み込めないとき (控えにある型が今の版に無い、など) は、ゲームはそのまま続き、理由を知らせに出す。
- 控えは lider を閉じるまで。file には残さない。

## ゲームの値を書き換える

- 書き換えるのは、コードの保存では入れられない物 (動いている個体の状態)。定数は、コードを直して保存する。
- 書けるのは、ゲームを止めている間だけ。動いている間は読むだけ。
- 書く場所は、`Inspector` の値と、コードの行の後ろの値の両方。押すと新しい値を打て、bool は押すだけで反転する。
- 書いた値は、止めた frame の状態に入り、絵もその値で描き直す。続けるか 1 frame 進めると、その値から動く。書いた frame より後の控えた frame は捨て、前の frame へは戻れる。
- 値を書く口は lub に置く (`Sys.InspectSet`。`Sys.Inspect` と同じ path で、開いた app を調べる側が誰でも使える)。

## 入力

- キーボードは focus のあるウィンドウへ、マウスは指している一番手前のウィンドウへ、gamepad はゲームへ送る。
- 編集、試す、ゲームだけの 3 つの状態 (`Workspace.Active`、`Lider.GameOnly`) は消す。
- F1 で、focus をゲームの窓と `Code` の間で移す。
- ゲームの絵だけを出すのは、命令で行う (起動したときも、ゲームの絵だけを出す)。ゲームの絵の無いスクリーンは出さず、ゲームの絵と同じスクリーンに並ぶほかのウィンドウは、並びの順番を保ったまましまう。
- ゲームが動いている間は、ゲームの窓へのマウスの入力は、全部ゲームに渡す。ゲームの窓をクリックすると focus もゲームの窓に移り、`Code` をクリックすると focus が `Code` に移る。その間もゲームは動き続ける。
- ゲームを止めている間だけ、ゲームの窓の中の物を指して、それを描いたコードを調べたり開いたりできる。動いている間に左クリックや中クリックでコードを開く操作はやめる。

## 命令と key

- 操作は、名前の付いた命令として持つ (`Inspector` を開く、規則を替える、ウィンドウを閉じる、など)。
- どの命令も、Ctrl+P の検索から名前で呼べる。検索には、file と宣言のほかに命令も並べる。
- key は命令への割り当てにすぎない。
- 割り当ては、利用者が変えられる。既定の割り当ての上に、変えた分を重ねる。
- 変えた分は、利用者ごとの file に書く (プロジェクトごとではない。key の好みは人に付く)。1 行に「key 命令」を書いたテキスト。
- 変えるには、命令 (`keys:set`) で命令を選び、次に押した key を割り当てる。Esc は取り消しで、割り当てられない。命令 (`keys:reset`) で既定に戻す。
- 割り当てられるのは、Ctrl か Alt を付けた key と、F key。focus をゲームから戻す key は、ほかの命令に取らせない。
- 検索と案内に出す key は、今の割り当てから引く。
- key と命令の表は 1 つにする。lider の操作も、エディタの命令と同じ表に載せ、key ごとの分岐を直に書かない。命令は、今の focus で効くかを自分で答える。
- 修飾 key で、何に効くかを分ける。修飾なしと Shift は、focus のあるウィンドウの中身への入力。Ctrl は、中身への操作 (保存、検索、取り消し、定義へ飛ぶ)。Alt は、ウィンドウとスクリーンへの操作 (focus を移す、並びを変える、大きさ、規則を替える、別のスクリーンへ移す)。
- 閉じる (Ctrl+W) とタブを移る (Ctrl+Tab) は、世の中のエディタの慣れに合わせて Ctrl のままにする。
- F key は、修飾なしの 1 押しで繰り返し押す操作にだけ使う。あてはまるのは、ゲームの時間の操作 (止める、1 frame 戻す / 進める、作り直す)、focus をゲームと `Code` の間で移す F1、エディタの「次を探す」の F3。機能が増えるたびに F key を足さない。
- エディタの中の割り当ては、世の中のコードエディタの慣れに合わせる (F3 で次を探す、Ctrl+G で行へ飛ぶ)。
- key を振るのは、よく使う物だけ。迷ったら振らず、Ctrl+P から名前で呼ぶ。
- focus がゲームにある間、lider が取る key は、focus を戻す key の 1 つだけ。ほかは全部ゲームに渡す。
- 隣のウィンドウへ focus を移す操作 (Alt+矢印) は、同じスクリーンの中で、見た目で隣にあるウィンドウへ移る。別のスクリーンのウィンドウとは、重なっていると隣かどうかを決められないので、別の命令にする。

## 決めていないこと

- 既定の割り当てを、どの命令にどの key にするか (考え方は「命令と key」のとおり)。今の既定は仮の物: Ctrl+B で定義へ飛ぶ、Ctrl+E で次のエラーへ、Alt+Enter で画面いっぱい、Alt+L で次の配置へ、Alt+I で `Inspector`、Alt+D で編集中の版を並べる。既定で key を振っていない命令は、ゲームの絵だけを出す、負荷の一覧、状態を写す、音と演出、差分の出し方、file を消す、次のスクリーンへ移す、配置を控える、固定先を替える、key を変える。
- 操作の案内、検索、アセットのウィンドウに、見出しの帯と閉じる印を出すか (今は出していない)。
- 範囲 (`LIDER_AREA`) を、スクリーンの大きさと場所で言い直すか (今は、控えた frame の帯だけ、ゲームの絵のうち範囲に入る所の下の端に置いている)。
- 別のスクリーンのウィンドウへ focus を移す命令。

- ウィンドウそのものに奥行きの大きさを持たせるか (ゲームの場面を、スクリーンの上の決まった大きさの箱の中に立体で出す形)。作って見ないとわからない。
- ゲームの場面をワールドにそのまま描いた物が複数重なるときの出し分け方 (透過度、目ごと)。やってみないとわからない。決まるまで、`Space` に置ける `GameView` は 1 つにする。
- ウィンドウを持って動かしたときにできること。順番を変えるほかに、規則を替える、別のスクリーンに移す、などが増えそう。
- XR で、操作の案内 (`hud`)、検索 (`palette`)、重ねる形の `backdrop` をどこに置くか (今は `ScreenAnchor.View` で、頭に付く)。
- XR で、控えた frame の帯を出す (今は画面に直に描いているので、XR では出ない)。
- スクリーンを利用者が作る、消す、大きさを変える操作。
- 控えた配置を消す命令。
